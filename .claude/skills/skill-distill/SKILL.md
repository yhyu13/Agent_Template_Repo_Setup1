# skill-distill · 会后沉淀流水线

## 何时调

- 一段活儿刚做完、PR 已合、准备收工或汇报时；
- 用户说"沉淀 / 存成 skill / 记下来 / 以后别再踩"；
- 路上踩了坑、发现反直觉的事实、验证命令跑通了，值得留给下一个会话；
- 定期（每个版本节点）体检已有 skill 是否过时、重复、膨胀。

**不调的情况**：只想把进度记一笔 → 那是 journey / inbox，不是 skill。
分不清时问一句：这条是"这次做了什么"（进度），还是"下次该怎么判断和怎么做"（skill）？后者才沉淀。

## 一、判定：什么值得沉淀（过四道闸）

四道全过才写 skill；任何一道不过就走 inbox 或干脆不写。

| 闸 | 判断 | 不过怎么办 |
|---|---|---|
| ① 可复用 | 下次遇到同类任务，这段话能直接省掉一次踩坑？ | 只记进度 → inbox |
| ② 有判断 | 含"该选 A 还是 B、什么时候该停"的决策，不只是"我敲了这些命令" | 命令清单 → 直接进文档 |
| ③ 有证据 | 能指回具体文件/命令/错误码/真源，不是"我觉得" | 先补齐证据再沉淀 |
| ④ 有边界 | 说清了什么时候**不**适用 | 补一节"不调的情况" |

反模式（不要沉淀）：抄 README/代码副本；单次事故流水账（除非揭示会复发的机制）；通用编程常识；把 skill 写成日志。

## 二、粒度与归属

- 命名 kebab-case；一个 skill ≈ 一条链路；超过 ~150 行考虑拆。
- `description` 写成**召回条件**（"什么时候该用"），不是内容摘要。
- 新建前先扫 `.claude/skills/`：能塞进已有 skill 就追加，塞不下才新建。
- 一条坑只在一个 skill 里出现一处；定期实跑关键命令，跑不通的当场改或删；*过时比缺失更糟*。

## 三、写法

每条经验三段式：`结论` → `为什么（带证据：文件/命令/错误码）` → `怎么防再犯（可断言的那一步）`。

## 四、流程与红线

- 沉淀走分支 + PR + squash merge；禁直推 main、禁本地 merge。
- ❌ 不入库密钥；❌ 不搬历史日志 entry；❌ 进度冒充方法；❌ 未验证的命令写进 skill。
- ✅ 沉淀的是**判断与边界**，不是日志与副本。
