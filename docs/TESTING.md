# 验证分级

<!-- fill later on demand: 骨架。有真实测试体系后，把每一级换成具体命令与适用改动类型。 -->

按「改动是否依赖真实的时间、网络、设备」定级别，能低不高：

| 级别 | 名称 | 适用 | 形态 |
|---|---|---|---|
| L1 | 静态 | 纯语法/类型/格式改动 | lint / typecheck |
| L2 | 行为 | 有逻辑变更，不依赖外部环境 | 单测/集成测试 |
| L3 | 构建 | 动了构建链、依赖、入口 | 本地完整 build（*CI 绿不等于能构建*） |
| L4 | 真实环境 | 依赖真机、真实网络、真实数据 | 一次性环境 e2e + 人工验收 |

DELETED-ON-PURPOSE: 本模板不内置 e2e 框架选型——各项目差异太大，强行给一个只会是错的。

## 为什么必须分级（而不是"跑一下测试"）

三次最贵的翻车，缺的是**不同级别**的验证。把这张表填上真实事故，它就成了选级别的依据：

| 事故 | 缺的是哪一级 | 当时的表现 |
|---|---|---|
| <一次构建失败的上线> | **L3** | CI 刻意不含 build，语法错误到生产才暴露 |
| <一次性能/累积效应退化> | **L2 太弱** | mock 同步返回，单测全绿但真实路径退化；也没有可复现基准 |
| <一次本地全绿、真实环境全灭> | **L4** | 代码正确、CI 全绿，但真实网络 / 真机不成立 |

规则：**出了事故先写清"缺的是哪一级"，再决定加门禁还是加验证**。写不清就先别加——否则
加的多半是重复的那一级。

## 验证必须独立

- 实现者自己跑的叫"自检"，不是验证。分级证据由**另一个人**（另一个会话或另一个 agent）
  产出，记录「在哪跑 / 什么命令 / 观察到什么 / 哪一级没做」。
- "L2 全绿"不等于"已验证"：要说清 L3、L4 是**没做**还是**不适用**。没做就写没做。
- mock 越快，越能掩盖真实退化。凡是"改动依赖真实的时间、网络、设备"，L2 全绿只算入场券。

## 如果这个仓库只做得起三件事

1. **开工先查 `memory/symptom-routing.md`**，收工补一行——防的是"打开错的文件、重踩旧坑"。
2. **验证独立且分级**——防的是自证与 mock 掩盖。
3. **发布前本地 build 必须过**（L3）——防的是"CI 绿但构建不了"。

这三条各自覆盖不同事故，不能互相替代：分级验证防不住"根本没跑构建"，L3 也防不住
"构建过了但真机不成立"。按事故覆盖率挑，不要按完整度挑。
